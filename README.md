# Арена переговоров

[Открыть тренажёр](https://chernozemual.github.io/negotiation-arena/) · [Исходный код](https://github.com/chernozemUal/negotiation-arena) · [Презентация](https://chernozemual.github.io/negotiation-arena/presentation/)

Работающий учебный MVP по ТЗ «ОЭЗ ППТ Алабуга». Полноценные шестишаговые переговоры с безопасной повторной попыткой, голосовым режимом и разбором конкретных решений.

## Запуск

Нужны Node.js 22+ (версия зафиксирована в `.nvmrc` и `engines`) и npm. Проверяемый браузер: Chromium/Chrome.

```bash
npm ci
npm run build
npm start
```

Открыть http://localhost:3000. Для разработки: `npm run dev`. Установка требует интернет. Для сценарного режима ключи и переменные окружения не нужны. При подключении пользователем собственного ключа браузер обращается напрямую к OpenAI. Зависимости зафиксированы в package-lock.json.

## Продукт и путь пользователя

Аудитория: начинающие руководители и руководители проектов, закупщики, сотрудники, готовящиеся к карьерному разговору, HR и корпоративные тренеры. Проблема: знание теории не даёт безопасной регулярной практики. Ценность: короткий повторяемый диалог, видимые последствия выбора и обратная связь на собственные реплики.

Путь: приветственная легенда → карта переговоров → брифинг → шесть этапов диалога → разбор → рост XP и новое звание → открытие следующего масштаба переговоров. Карта содержит восемь уровней: городские, региональные, федеральные и международные переговоры. В основе уровней три полноценных сюжета: контракт с поставщиком, карьерный разговор и конфликт «срочный релиз против выгорания команды». Каждый этап содержит три тактики, свободный текст и голосовой ввод. На каждом этапе реакция собеседника ветвится: сильный ход открывает сделку, слабый стоит переговорной позиции, давление ожесточает собеседника. При напряжённости от 70% вместо нейтрального варианта появляется ветка «восстановить контакт». Финалы: договорённость, отсутствие договорённости, досрочное завершение и срыв сделки при 100% напряжённости; у каждого сюжета свой текст последствий на экране разбора.

### Игровые механики

- **Варианты без подсказки порядком.** Три тактики этапа перемешиваются для каждой сессии: лучший ход не всегда первый. Порядок стабилен после перезагрузки. Среди вариантов есть правдоподобные ловушки: деловой торг без контакта, изложение только своей позиции, размытая фиксация «детали по почте».
- **Скрытые интересы собеседника (Гарвардский метод).** У каждого собеседника три интереса за позицией: например, у поставщика это загрузка производства, сроки оплаты и горизонт контракта. Интерес раскрывается, когда реплика игрока его затрагивает; сценарный движок распознаёт это по ключевым словам. Каждый раскрытый интерес повышает доверие. Свободная реплика с интересом также даёт очки и снижает напряжённость, а собеседник в ответ рассказывает об этом интересе. Прогресс «интересы N/3» виден во время встречи, а в разборе есть вкладка с тем, что осталось нераскрытым, и подсказкой, как это спросить.
- **Таймер под давлением.** При напряжённости от 70% собеседник торопит: на ответ даётся 45, 35 или 25 секунд в зависимости от сложности. Если время вышло, черновик от 15 символов отправляется как есть, иначе засчитывается «молчание под давлением»: минус доверие и плюс напряжённость. Таймер отключается в настройках.
- **Голос и клавиатура.** При первой встрече над полем ответа появляется подсказка про голосовой ввод; если браузер его не поддерживает, подсказка это объясняет. На компьютере варианты выбираются клавишами 1–3.

## Демонстрация для жюри (3–5 минут)

1. В конструкторе выбрать сферу, тему, сложность, тон, роль и цель. Сохранить. Нажать «Протестировать».
2. В первом прогоне выбрать конструктивные ответы на шести этапах; открыть разбор.
3. Повторить с угрозами и уступками: сравнить доверие, очки и исход. Два хода давления подряд доводят напряжённость до 70%+: появляются таймер на ответ и ветка «восстановить контакт».
4. Показать прогресс и перезагрузить страницу: результаты сохранятся.
5. Презентация доступна по `/presentation`, готовый PDF — `public/arena-presentation.pdf`; её можно показать в браузере или сохранить в PDF через печать. Для сдачи разместить репозиторий и приложить ссылки на документацию и презентацию.

## Архитектура и методы

Next.js App Router + TypeScript; Tailwind CSS и собственные CSS-компоненты; Lucide React; Framer Motion; Zustand persist. `lib/engine.ts` отвечает за сценарии, оценку, напряжённость и исход; `lib/progression.ts` — за восемь званий и карту; `lib/teacher.ts` — за локальный профиль преподавателя и перенос отчётов; `lib/store.ts` — за активную сессию и историю. Серверной БД нет: localStorage хранит настройки, активную сессию и последние 50 результатов в этом браузере. Очистка данных браузера удалит прогресс. XP и звание рассчитываются по сохранённой истории.

Сфера подбирает один из трёх сюжетов. Сложность меняет необходимый результат (52/65/78 из 100) и цену ошибок: на продвинутом уровне потеря доверия и рост напряжённости от враждебных ходов умножаются на 1,15, на экспертном — на 1,3. Тон меняет первую реплику, стиль ответов и стартовое напряжение; цель включается в обсуждение интересов. Роль и тема отображаются в контексте; в режиме OpenAI тема, роль, цель и первая реплика передаются модели. Произвольные темы не генерируют новые сюжеты: для этого нужен будущий редактор сценариев. Доверие стартует с 50%, действия изменяют его, при падении ниже 25% собеседник предупреждает об остановке. Для успеха нужны все 6 этапов, порог баллов и доверие минимум 40%. Баллы нормализуются до шкалы 0–100. Время измеряется без принудительного лимита.

Напряжённость — отдельный показатель от 5 до 100%. На старте дружелюбный, сдержанный и жёсткий тон задают 24, 36 и 48%; продвинутый уровень добавляет 5 пунктов, экспертный — 10. Давление повышает напряжение, конструктивные действия снижают его. На 45% появляется осторожный диалог, на 70% — состояние на грани срыва и учащающееся тиканье. При достижении 100% сделка немедленно срывается и открывается разбор. Показатель вычисляется по настройкам сессии и истории ходов, поэтому восстанавливается после перезагрузки.

В настройках доступны спокойный режим, повтор легенды, профиль ученика, локальный вход преподавателя и BYOK-подключение OpenAI. Пользователь вставляет свой API-ключ и запускает проверку доступа; при подключённом API приложение всегда использует `gpt-5.6-sol`. По умолчанию ключ хранится в `sessionStorage` до закрытия вкладки; постоянное сохранение в `localStorage` включается отдельным флажком. Ключ не попадает в исходный код, GitHub или базу приложения. После подключения OpenAI генерирует реплики собеседника, а локальный движок продолжает считать очки, доверие и напряжённость. При ошибке API сессия автоматически использует сценарный ответ.

Аккаунт преподавателя защищён локальным PIN, хеш которого хранится на устройстве. Ученик копирует код отчёта, преподаватель импортирует его и видит количество сессий, договорённости, средний балл, XP, звание и последние попытки. Это рабочий обмен между устройствами без сервера; автоматическая синхронизация потребует базы данных и серверной авторизации.

Клиентское хранение ключа менее безопасно, чем серверная интеграция: любой JavaScript, исполняющийся на странице, потенциально имеет к нему доступ. Этот режим добавлен для личного тестирования на статическом GitHub Pages по модели «свой ключ». Для общего корпоративного использования следует перенести вызов OpenAI на сервер и хранить ключ в секретах хостинга. Запросы могут тарифицироваться в аккаунте владельца ключа. Для генерации используется Responses API с `store: false`; проверка подключения запрашивает метаданные `gpt-5.6-sol` без генерации текста.

Свободный текст оценивается прозрачной эвристикой по ключевым признакам текущего этапа и давления. Оскорбления ищутся с начала слова, поэтому «плохо» или «хлеба» не считаются грубостью. Ультиматум распознаётся по угрозе, а не по отдельному слову «иначе». Извинение засчитывается как восстановление контакта только после конфликтного хода, поэтому повтор «извините» не приносит победу. Это не LLM, не семантическая оценка и не валидированный психометрический тест. Разбор предлагает учебные рекомендации. Уровни и XP мотивируют повторять практику, но не подтверждают профессиональную квалификацию.

## Границы MVP

Нет серверной регистрации и автоматической синхронизации устройств. Локальный кабинет преподавателя предназначен для демонстрации и ручного импорта отчётов; для закрытого корпоративного кабинета нужна серверная авторизация. При включённом OpenAI текст диалога отправляется в API для генерации ответа. Голосовой ввод использует браузерный Web Speech API и требует разрешения на микрофон; в Chrome распознавание может выполняться внешним онлайн-сервисом браузера и не работать офлайн. Автоозвучка по умолчанию выключена. После включения она предпочитает доступный системе русский голос с именем Alice/Алиса, Alena/Алёна или Yandex, затем выбирает ближайший русский женский голос. Публичный SpeechKit нельзя вызвать напрямую со статической страницы из-за CORS, поэтому гарантированный облачный голос потребует серверного прокси. Настройки новой сессии не меняют уже начатую.

## Проверки

```bash
npm test
npm run typecheck
npm run build
```

Тесты проверяют перемешивание вариантов, раскрытие скрытых интересов, штраф за молчание по таймеру, успешные/неуспешные пути всех шестишаговых сценариев, невозможность успеха незавершённой сессии, срыв сделки при 100% напряжённости, нормализацию баллов, влияние настроек на реакции, пороги и обработку свободных реплик. Проверки напряжённости охватывают влияние тона и сложности, рост при давлении, снижение при конструктиве, границы на всех ветках, отличие от доверия и восстановление из сохранённых ходов.

## Обновлённый интерфейс

Меню и основные кнопки занимают один экран. История реплик, длинная история сессий, формы на небольших дисплеях и подробный разбор прокручиваются внутри своих панелей; страница целиком не прокручивается. Разбор разбит на переключаемые этапы. Шрифт полей ввода на мобильных устройствах — 16 px для удобного ввода без автоматического увеличения страницы.

Первое знакомство состоит из четырёх глав: легенда, навигация, реплики и напряжённость, результаты и настройки. Его можно пропустить или повторить из настроек. Тёмная тема включена при первом запуске; светлая получила более контрастные границы и текст. Тема, звуковые эффекты, автоозвучивание и спокойный режим сохраняются локально. Анимации учитывают `prefers-reduced-motion`; каждую реплику соперника можно озвучить повторно.

Черновик свободной реплики сохраняется вместе с текущей сессией, включая переходы между экранами и перезагрузку. Повтор из истории сначала открывает брифинг: при активной сессии видимо предупреждение о её замене.

## Сверка с техническим заданием

- **Продукт и концепция:** указаны аудитория, проблема, ценность относительно лекций и ролевых тренингов, полный путь от входа до повторной попытки.
- **Сценарии и влияние стратегии:** реализованы три шестишаговых сценария (закупки, карьера, команда) с конструктивными, нейтральными и конфликтными ветками и веткой восстановления контакта; формулировки меняют баллы, доверие, напряжённость, ответ собеседника и финал.
- **Конфигурируемость:** конструктор задаёт сферу, тему, сложность, тон, роль и цель; настройки участвуют в брифинге, пороге успеха, стартовом напряжении и ответах.
- **Контуры пользователя и администратора:** практика, прогресс и разбор отделены от конструктора контекста.
- **Геймификация и UX/UI:** восемь званий с уникальными знаками, XP-анимация, карта из восьми переговоров, состояние собеседника, две темы, адаптивная навигация, звук, озвучивание и голосовой ввод.
- **Воспроизводимость:** публичный деплой, открытый код, зафиксированные зависимости и запуск тремя командами. Платный API необязателен: оба сценария полностью проходят автономно.
- **Материалы финальной сдачи:** README служит сопроводительной документацией, `/presentation` и `public/arena-presentation.pdf` содержат презентацию, ссылки на прототип и репозиторий размещены в начале файла.

Границы относительно будущего корпоративного продукта: произвольная тема пока уточняет один из трёх подготовленных сюжетов, кабинет преподавателя хранится локально, результаты переносятся кодом вручную, а учебная эвристика требует проверки тренерами.

## Публичная тестовая версия

Хостинг — GitHub Pages из ветки `gh-pages`. Исходники находятся в `main`; в `gh-pages` попадает только статическая сборка и `.nojekyll`. Для обновления сайта: `npm run deploy` (нужны Git и авторизованный GitHub CLI). Скрипт запускает тесты, собирает сайт и публикует артефакты без принудительной перезаписи истории. Публичная версия работает без сервера; OpenAI включается ключом конкретного тестировщика. Каждый тестировщик получает собственные настройки и прогресс в своём браузере; общей базы результатов нет.

Для публикации используется `STATIC_EXPORT=true`, а `NEXT_PUBLIC_BASE_PATH` указывает на имя репозитория. Внутренние ссылки используют Next.js Link и учитывают путь репозитория. В обычном локальном запуске эти переменные не нужны.

Сообщить об ошибке можно через [GitHub Issues](https://github.com/chernozemUal/negotiation-arena/issues). Укажите устройство, размер экрана, сценарий, шаги и ожидаемый результат.

Необязательный шаблон автоматического деплоя через Actions сохранён в `docs/deploy-pages.workflow.yml`. Для его активации потребуется право `workflow`; текущая публикация этого права не требует.
