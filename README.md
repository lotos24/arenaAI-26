# Арена переговоров

[Открыть тренажёр](https://lotos24.github.io/arenaAI-26/) · [Исходный код](https://github.com/lotos24/arenaAI-26) · [Презентация](https://lotos24.github.io/arenaAI-26/presentation/)

Работающий учебный MVP по ТЗ «ОЭЗ ППТ Алабуга». Полноценные шестишаговые переговоры с безопасной повторной попыткой, голосовым режимом, локальной нейросетью прямо в браузере (WebLLM, без API-ключей) и разбором конкретных решений. Отраслевые кейсы заказчика — «Завод в ОЭЗ „Алабуга“» и «Алабуга Политех» — открыты на карте с первого запуска.

## Запуск

Нужны Node.js 22+ (версия зафиксирована в `.nvmrc` и `engines`) и npm. Проверяемый браузер: Chromium/Chrome.

```bash
npm ci
npm run build
npm start
```

Открыть http://localhost:3000. Для разработки: `npm run dev`. Установка требует интернет. API-ключи и переменные окружения не нужны: сценарный режим полностью автономен, а локальная нейросеть скачивает веса один раз прямо в браузер. Зависимости зафиксированы в package-lock.json.

## Продукт и путь пользователя

Аудитория: начинающие руководители и руководители проектов, закупщики, сотрудники, готовящиеся к карьерному разговору, HR и корпоративные тренеры. Проблема: знание теории не даёт безопасной регулярной практики. Ценность: короткий повторяемый диалог, видимые последствия выбора и обратная связь на собственные реплики.

Путь: приветственная легенда → карта переговоров → брифинг → шесть этапов диалога → разбор → рост XP и новое звание → открытие следующего масштаба переговоров. Карта содержит десять уровней: два кейса ОЭЗ «Алабуга», открытые сразу, и восемь уровней по званиям — городские, региональные, федеральные и международные переговоры. В основе уровней три полноценных сюжета: контракт с поставщиком, карьерный разговор и конфликт «срочный релиз против выгорания команды». Каждый этап содержит три тактики, свободный текст и голосовой ввод. На каждом этапе реакция собеседника ветвится: сильный ход открывает сделку, слабый стоит переговорной позиции, давление ожесточает собеседника. При напряжённости от 70% вместо нейтрального варианта появляется ветка «восстановить контакт». Финалы: договорённость, отсутствие договорённости, досрочное завершение и срыв сделки при 100% напряжённости; у каждого сюжета свой текст последствий на экране разбора.

### Игровые механики

- **Варианты без подсказки порядком.** Три тактики этапа перемешиваются для каждой сессии: лучший ход не всегда первый. Порядок стабилен после перезагрузки. Среди вариантов есть правдоподобные ловушки: деловой торг без контакта, изложение только своей позиции, размытая фиксация «детали по почте».
- **Скрытые интересы собеседника (Гарвардский метод).** У каждого собеседника три интереса за позицией: например, у поставщика это загрузка производства, сроки оплаты и горизонт контракта. Интерес раскрывается, когда реплика игрока его затрагивает; сценарный движок распознаёт это по ключевым словам. Каждый раскрытый интерес повышает доверие. Свободная реплика с интересом также даёт очки и снижает напряжённость, а собеседник в ответ рассказывает об этом интересе. Открытый вопрос о приоритетах («что для вас важнее всего?», «какие у вас ограничения?») даёт зацепку: собеседник называет тему, которую ещё не обсуждали, а раскроется интерес, когда игрок её подхватит. Прогресс «интересы N/3» виден во время встречи, а в разборе есть вкладка с тем, что осталось нераскрытым, и подсказкой, как это спросить.
- **Собеседник отвечает на ваши слова.** Свободную реплику движок разбирает не только ради оценки: он замечает приветствие, вопрос, контрольный вопрос «правильно ли я понимаю», названную цифру («5%», «три месяца»), предложение с обменом, эмпатию и согласие «на всё». Ответ собирается из реакции на это, позиции этапа и того, чего в ходе не хватило, сказанного голосом собеседника («И что вы готовы дать взамен?»). Цифру, которую первым назвал сам собеседник, он не принимает за предложение игрока. Вежливый, но пустой ход считается слабым, а не враждебным: доверие не падает. Род персонажа учитывается («готов» или «готова»).
- **Живой собеседник.** У каждого этапа по четыре формулировки позиции и по три способа попросить недостающее; жёсткий собеседник говорит короче и резче, дружелюбный — теплее. Одна и та же реплика даёт один и тот же ответ, разные реплики — разные.
- **Таймер под давлением.** При напряжённости от 70% собеседник торопит: на ответ даётся 45, 35 или 25 секунд в зависимости от сложности. Если время вышло, черновик от 15 символов отправляется как есть, иначе засчитывается «молчание под давлением»: минус доверие и плюс напряжённость. Таймер отключается в настройках.
- **Голос и клавиатура.** При первой встрече над полем ответа появляется подсказка про голосовой ввод; если браузер его не поддерживает, подсказка это объясняет. На компьютере варианты выбираются клавишами 1–3.
- **Просторный диалог.** Варианты ответа стоят в ленте переписки под последней репликой собеседника, а внизу закреплены только поле ввода и строка этапа. Пока игрок пишет свой ответ, варианты убираются и переписка занимает всю высоту; кнопка «Скрыть варианты» прячет их совсем. Лента после ответа прокручивается к началу новой реплики.

### Локальная нейросеть (WebLLM)

- **Без ключей и серверов.** Реплики собеседника может формулировать языковая модель Qwen2.5-Instruct, которая работает прямо в браузере через WebGPU ([WebLLM](https://github.com/mlc-ai/web-llm)). В настройках есть карточка «On-Device нейросеть»: индикатор поддержки WebGPU, тумблер, выбор модели, кнопка загрузки с прогрессом и удаление из кэша. В шапке показан статус: «Локальный AI (WebGPU) активен» или «Сценарный режим (WebGPU недоступен / нейросеть выключена)».
- **Модели.** «Качественная» Qwen2.5-1.5B (≈1 ГБ, по умолчанию) и «Быстрая» Qwen2.5-0.5B (≈0,4 ГБ). В наших проверках 0.5B часто писала по-русски с ошибками, выходила из роли и сбивалась на списки, поэтому по умолчанию выбрана 1.5B. На видеокартах без f16-шейдеров автоматически берётся сборка q4f32. Веса скачиваются один раз с Hugging Face в Cache Storage браузера, дальше модель запускается без сети. Нужны WebGPU (Chrome/Edge 113+) и 1–2 ГБ видеопамяти. Пакет подключается динамическим `import()` и работает в Web Worker, поэтому не утяжеляет стартовую загрузку и не подвешивает интерфейс.
- **Модель говорит, но не решает.** Очки, доверие, напряжённость и исход считает прозрачный сценарный движок, и он же собирает суть ответа, которая уже реагирует на слова игрока: на вопрос, цифру, предложение. Модель получает роль, цель, тон, историю, реплику игрока и эту суть и произносит её своими словами живой речью, не добавляя согласий, отказов, цифр и вопросов. В проверках Qwen2.5-1.5B, которой дали отвечать свободно, путала роли («Хорошо, Алина…» от самой Алины) и превращала итоговое «так и зафиксируем» в «давайте пересмотрим», поэтому суть закреплена. Слабые и неуклюжие свободные реплики тоже идут в модель. На ультиматумы, требования, оскорбления и молчание собеседник всегда отвечает детерминированно: маленькие модели склонны соглашаться с давлением.
- **Фильтр ответа.** Ответ модели отбрасывается, если в нём иероглифы или латиница, служебные пометки («Вот пример ответа»), если он потерял суть (нужно два общих смысловых слова с ней или одно, если ответ подхватывает слова игрока), заметно длиннее сути, копирует реплику игрока, говорит за игрока (имя персонажа, вопрос о «ваших» интересах вместо собственного утверждения) или меняет согласие на отказ. Эхо-обращение по имени персонажа вырезается, пересказанный диалог обрезается до последней пометки «Ты:».
- **Второй оценщик.** Когда модель загружена, она проверяет свободную реплику: находит элементы этапа, которые ключевые слова не распознали, и для каждого приводит точную цитату. Засчитывается не больше двух элементов по 2 балла, в пределах максимума этапа, и только если цитата действительно есть в реплике, в ней хотя бы два слова и она похожа на свой критерий (вопрос — на вопрос, «несколько параметров» — хотя бы на два параметра). Если модель поставила цитату под чужой номер, она идёт к подходящему недостающему критерию. В разборе видно, что засчитала нейросеть и по какой цитате. Проверено на Qwen2.5-1.5B: разбор понимает её реальные ответы («1. номер: «…»»), а скопированный из промпта пример не засчитывается.
- **Надёжная генерация.** WebLLM оставляет флаг прерывания взведённым, если `interruptGenerate()` вызвать без идущей генерации, и тогда все следующие обычные запросы возвращают пустую строку. Арена прерывает только идущую генерацию и получает ответ потоком: потоковый запрос сбрасывает флаг, поэтому переход в настройки или завершение встречи больше не «глушат» модель до перезагрузки. Сценарная реплика подставляется мгновенно и при отсутствии WebGPU, до загрузки модели, при таймауте в 25 секунд или ошибке.

### Отраслевые кейсы и свои сценарии

- **ОЭЗ «Алабуга».** «Инвестиции: размещение завода в ОЭЗ „Алабуга“» — сложность «Эксперт», жёсткий тон, условия входа резидента и аренда корпуса «Синергия». Скрытые интересы: объём инвестиций первой очереди, стабильное техприсоединение на 15 МВт, локализация поставщиков. BATNA: альтернативная площадка в соседнем регионе. «Алабуга Политех: привлечение инженера-наставника» — «Продвинутый», сдержанный тон. Интересы: служебное жильё в Елабуге, авторская свобода в программе обучения, KPI по трудоустройству выпускников.
- **Своя тема — свои реплики.** Если тема в конструкторе совпадает с одним из готовых сюжетов, используются авторские реплики. Если администратор вводит свою тему, брифинг, первая реплика, варианты ответа, реакции собеседника, рамка и финал строятся из шаблонов с `{topic}`, `{role}` и `{goal}`, а скрытые интересы берутся общие: риски, сроки, обоснованная выгода.
- **Расширенный JSON.** Экспорт и импорт сценария поддерживают блок `custom`: персонаж, брифинг, первая реплика, рамка (goal/batna/zopa) и до пяти скрытых интересов с ключевыми словами и репликой раскрытия. Каждое поле проверяется при импорте.

### Геймификация и обучение

- **Достижения.** Шесть наград: «Гарвардский дипломат» (все интересы за сессию), «Стальные нервы» (договориться на «Эксперте» с жёстким собеседником), «Решение под прессингом» (сильный ответ меньше чем за 5 с до конца таймера), «Win-Win Мастер» (90+ баллов), «Живое слово» (3 этапа голосом), «Мастер деэскалации» (снизить напряжённость после всплеска выше 75%). При получении показывается уведомление, витрина — на экране «Прогресс».
- **Было ➔ Стало.** «Попробовать иначе» запоминает прошлую попытку. В разборе видна динамика баллов, доверия, напряжённости и числа ошибок, у метрик — изменение к прошлой попытке. Повтор честный: движок детерминированный, поэтому собеседник и его скрытые условия те же, что в прошлой попытке, и изменение результата объясняется только стратегией игрока. Об этом напоминают брифинг повтора и первая строка диалога.
- **Итог сделки отдельно от оценки навыка.** Разбор открывается вкладкой «Итог»: статус (договорённость, частичная, не достигнута, отложена, срыв), что договорились — условия, цифры, ответственный и срок, взятые из реплик игрока, — что важно собеседнику и «Цена результата»: уступки без встречного условия, давление с его ценой в доверии и напряжённости, нераскрытые интересы, итог без ответственного и срока. Соглашение не считается хорошей игрой само по себе.
- **Три судьи.** Вкладка «Судьи» — в духе управленческих поединков Владимира Тарасова: «Пошёл бы я работать под руководством этого человека?», «Отправил бы я его вместо себя на сложные переговоры?», «Доверил бы я ему свои ресурсы?». У каждого вердикт, сильный и слабый эпизод — цитата игрока, этап и время — и эффект хода: напряжённость до и после, изменение доверия, раскрытый интерес, первая фраза ответа собеседника. Вердикты считаются из ходов сессии мгновенно и одинаково при каждом просмотре.
- **Время реплик.** Каждый ход запоминает время от начала встречи; в разборе, у судей, в итоге сделки и в памятке реплики цитируются как «02:17 — «…»».
- **Подсказка коуча.** На уровнях «Базовый» и «Продвинутый» кнопка в поле ответа объясняет метод текущего этапа (эмпатия, SPIN, пакетный обмен, объективные критерии, фиксация) без готового ответа.
- **Ваша фраза — сильнее.** В разборе слабой свободной реплики показывается она сама, дополненная недостающим: признание риска ставится в начало, обмен, условие пересмотра или ответственный — в конец, добавленное подсвечено, а слова в [скобках] игрок подставляет сам. Готовый вариант из списка остаётся для сравнения.
- **Демо за минуту.** Кнопка на карте сама проходит кейс «Алабуга Политех»: вопрос об интересах даёт зацепку, подхваченная зацепка раскрывает интерес, давление поднимает напряжённость, контакт восстанавливается, пакет с пилотом снимает риск, договорённость фиксируется. Реплики печатаются в поле ввода, вариант с давлением подсвечивается перед выбором, над диалогом видна подпись шага и кнопка «Остановить демо». Демо отвечает выверенными сценарными репликами, чтобы на показе всё шло одинаково; маршрут проверяется тестом (договорённость, 2+ интереса, рост и спад напряжённости).

### Методики и аналитика

- **Контур администратора.** Экран «Администратор / Конструктор» содержит библиотеку из семи готовых кейсов, которые заполняют форму одним кликом: два кейса ОЭЗ «Алабуга», закупки, грейд и зарплата, горящий IT-релиз, B2B-скидка 25%, удержание тимлида при контроффере. «Экспорт сценария» копирует JSON настроек, «Импорт сценария» принимает такой JSON и проверяет каждое поле, так что методисты могут обмениваться кейсами.
- **Переговорная рамка.** В брифинге и в окне «Ваша задача» показаны цель, BATNA (наилучшая альтернатива соглашению) и ZOPA (зона возможных договорённостей) для текущего сюжета.
- **Бейджи методик.** Каждый ход относится к технике: «Гарвард: Интересы», «Гарвард: Пакетный обмен», «Гарвард: Объективные критерии», «SPIN: Ситуация», «SPIN: Исследование проблемы», «BATNA: Опора на альтернативу», «Эмпатия и контакт», «Фиксация договорённости». Рискованные тактики тоже подписаны: «Позиционный торг», «BATNA как угроза», «Давление», «Уступка без обмена». Бейдж видно в ленте после хода и в разборе. На уровне «Базовый» бейджи видны на карточках до выбора (учебный режим); на уровнях выше они скрыты, чтобы не подсказывать лучший ответ. Спокойное упоминание альтернативы в свободном тексте распознаётся как BATNA и добавляет очки, а угроза уходом — нет.
- **Оценка по Гарвардскому методу.** Во вкладке «Гарвард» разбора четыре принципа: отделение человека от проблемы, фокус на интересах (раскрытые интересы), взаимная выгода и объективные критерии. Каждый оценивается как «да», «частично» или «нет» с пояснением. Там же список раскрытых и нераскрытых интересов.
- **Матрица компетенций.** На экране «Прогресс» есть SVG-радар и пять шкал от 0 до 100%, которые считаются по истории сессий: эмпатия и контакт, исследование интересов (SPIN), пакетные решения, стресс-менеджмент, фиксация договорённостей. У каждой шкалы есть уровень: «Уверенно», «Хорошо», «Требует практики», «Начальный уровень». Без истории показаны ориентиры и подсказка пройти 1–2 переговоров.
- **Аналитика группы для HR.** В кабинете преподавателя по отчётам учеников считаются самый проблемный этап диалога (средняя доля от максимума баллов), процент срывов под давлением и наиболее западающая компетенция группы. Отчёты новой версии несут баллы по этапам и профиль компетенций; старые коды продолжают импортироваться.
- **Экспорт.** «Скопировать памятку по сессии» кладёт в буфер обмена текст с итогом, интересами, Гарвард-оценкой, сильными сторонами и рекомендациями; если буфер недоступен, памятка скачивается файлом .txt. «Экспорт группы в CSV» в кабинете преподавателя скачивает таблицу: ученик, класс, число сессий, средний балл, XP, звание, доля договорённостей и дата последней сессии. Разделитель — «;», в начале файла BOM, поэтому Excel корректно открывает кириллицу.

## Демонстрация для жюри (3–5 минут)

1. Открыть «Администратор / Конструктор». Выбрать готовый кейс из библиотеки или задать сферу, тему, сложность, тон, роль и цель. Сохранить, нажать «Протестировать» и показать в брифинге переговорную рамку (цель, BATNA, ZOPA).
2. Открыть кейс «Алабуга Политех» на карте. В первом прогоне выбрать конструктивные ответы или спросить своими словами про жильё, программу и трудоустройство выпускников — собеседник раскроет скрытые интересы. Открыть разбор и вкладку «Гарвард».
3. Повторить с угрозами и уступками: сравнить доверие, очки и исход. Два хода давления подряд доводят напряжённость до 70%+: появляются таймер на ответ и ветка «восстановить контакт».
4. Показать «Прогресс»: радар компетенций и витрину наград. Перезагрузить страницу — результаты сохранятся.
5. На ноутбуке с Chrome заранее загрузить модель в «Настройки → On-Device нейросеть», чтобы на показе реплики формулировала локальная нейросеть. Без WebGPU показ проходит в сценарном режиме.
6. Презентация доступна по `/presentation`, готовый PDF — `public/arena-presentation.pdf`; её можно показать в браузере или сохранить в PDF через печать. Для сдачи разместить репозиторий и приложить ссылки на документацию и презентацию.

## Архитектура и методы

Next.js App Router + TypeScript; Tailwind CSS и собственные CSS-компоненты; Lucide React; Framer Motion; Zustand persist. `lib/engine.ts` отвечает за сценарии, шаблоны своих тем, оценку, напряжённость и исход; `lib/web-llm.ts` — за локальную нейросеть (промпт, проверка ответа, загрузка модели в Web Worker); `lib/achievements.ts` — за награды; `lib/methods.ts` — за методики, Гарвард-оценку, компетенции и памятку; `lib/scenario-library.ts` — за готовые кейсы и JSON-сценарии; `lib/progression.ts` — за восемь званий и карту; `lib/teacher.ts` — за локальный профиль преподавателя и перенос отчётов; `lib/store.ts` — за активную сессию и историю. Серверной БД нет: localStorage хранит настройки, активную сессию и последние 50 результатов в этом браузере. Очистка данных браузера удалит прогресс. XP и звание рассчитываются по сохранённой истории.

Сфера подбирает один из трёх сюжетов. Сложность меняет необходимый результат (52/65/78 из 100) и цену ошибок: на продвинутом уровне потеря доверия и рост напряжённости от враждебных ходов умножаются на 1,15, на экспертном — на 1,3. Тон меняет первую реплику, стиль ответов и стартовое напряжение; цель включается в обсуждение интересов. Своя тема переключает реплики на шаблоны с темой, ролью и целью. Тема, роль, цель и первая реплика передаются и локальной модели. Доверие стартует с 50%, действия изменяют его, при падении ниже 25% собеседник предупреждает об остановке. Для успеха нужны все 6 этапов, порог баллов и доверие минимум 40%. Баллы нормализуются до шкалы 0–100. Время измеряется без принудительного лимита.

Напряжённость — отдельный показатель от 5 до 100%. На старте дружелюбный, сдержанный и жёсткий тон задают 24, 36 и 48%; продвинутый уровень добавляет 5 пунктов, экспертный — 10. Давление повышает напряжение, конструктивные действия снижают его. На 45% появляется осторожный диалог, на 70% — состояние на грани срыва и учащающееся тиканье. При достижении 100% сделка немедленно срывается и открывается разбор. Показатель вычисляется по настройкам сессии и истории ходов, поэтому восстанавливается после перезагрузки.

В настройках доступны локальная нейросеть, таймер под давлением, спокойный режим, повтор легенды, профиль ученика с мини-радаром компетенций и локальный вход преподавателя.

Аккаунт преподавателя защищён локальным PIN, хеш которого хранится на устройстве. Ученик копирует код отчёта, преподаватель импортирует его и видит количество сессий, договорённости, средний балл, XP, звание и последние попытки. Это рабочий обмен между устройствами без сервера; автоматическая синхронизация потребует базы данных и серверной авторизации.

Свободный текст оценивается прозрачной эвристикой по ключевым признакам текущего этапа и давления. Оскорбления ищутся с начала слова, поэтому «плохо» или «хлеба» не считаются грубостью. Ультиматум распознаётся по угрозе, а не по отдельному слову «иначе». Извинение засчитывается как восстановление контакта только после конфликтного хода, поэтому повтор «извините» не приносит победу. Оценку ставит не нейросеть: это не семантическая оценка и не валидированный психометрический тест. Разбор предлагает учебные рекомендации. Уровни и XP мотивируют повторять практику, но не подтверждают профессиональную квалификацию.

## Границы MVP

Нет серверной регистрации и автоматической синхронизации устройств. Локальный кабинет преподавателя предназначен для демонстрации и ручного импорта отчётов; для закрытого корпоративного кабинета нужна серверная авторизация. Локальная нейросеть не отправляет текст диалога наружу, но требует WebGPU и первичной загрузки весов; маленькая модель иногда отвечает неточно, поэтому её ответы проверяются и при сомнении заменяются сценарными. Голосовой ввод использует браузерный Web Speech API и требует разрешения на микрофон; в Chrome распознавание может выполняться внешним онлайн-сервисом браузера и не работать офлайн. Автоозвучка по умолчанию выключена. После включения она предпочитает доступный системе русский голос с именем Alice/Алиса, Alena/Алёна или Yandex, затем выбирает ближайший русский женский голос. Публичный SpeechKit нельзя вызвать напрямую со статической страницы из-за CORS, поэтому гарантированный облачный голос потребует серверного прокси. Настройки новой сессии не меняют уже начатую.

## Обновлённый интерфейс

Меню и основные кнопки занимают один экран. История реплик, длинная история сессий, формы на небольших дисплеях и подробный разбор прокручиваются внутри своих панелей; страница целиком не прокручивается. Разбор разбит на переключаемые этапы. Шрифт полей ввода на мобильных устройствах — 16 px для удобного ввода без автоматического увеличения страницы.

Первое знакомство состоит из четырёх глав: легенда, навигация, реплики и напряжённость, результаты и настройки. Его можно пропустить или повторить из настроек. Тёмная тема включена при первом запуске; светлая получила более контрастные границы и текст. Тема, звуковые эффекты, автоозвучивание и спокойный режим сохраняются локально. Анимации учитывают `prefers-reduced-motion`; каждую реплику соперника можно озвучить повторно.

Черновик свободной реплики сохраняется вместе с текущей сессией, включая переходы между экранами и перезагрузку. Повтор из истории сначала открывает брифинг: при активной сессии видимо предупреждение о её замене.

## Сверка с техническим заданием

- **Продукт и концепция:** указаны аудитория, проблема, ценность относительно лекций и ролевых тренингов, полный путь от входа до повторной попытки.
- **Сценарии и влияние стратегии:** реализованы три шестишаговых сценария (закупки, карьера, команда) с конструктивными, нейтральными и конфликтными ветками и веткой восстановления контакта; формулировки меняют баллы, доверие, напряжённость, ответ собеседника и финал.
- **Конфигурируемость:** конструктор задаёт сферу, тему, сложность, тон, роль и цель; настройки участвуют в брифинге, пороге успеха, стартовом напряжении и ответах.
- **Контуры пользователя и администратора:** практика, прогресс и разбор отделены от экрана «Администратор / Конструктор». В нём есть библиотека из пяти готовых кейсов и обмен сценариями через JSON. Кабинет преподавателя выгружает сводку группы в CSV.
- **Геймификация и UX/UI:** достижения, «Было ➔ Стало», подсказка коуча, восемь званий с уникальными знаками, XP-анимация, карта из десяти переговоров, состояние собеседника, две темы, адаптивная навигация, звук, озвучивание и голосовой ввод.
- **Воспроизводимость:** публичный деплой, открытый код, зафиксированные зависимости и запуск тремя командами. Платных API и ключей нет: сценарный режим проходит полностью автономно, нейросеть работает на устройстве. Сайт устанавливается как приложение (PWA: manifest, theme-color, apple-mobile-web-app-capable).
- **Материалы финальной сдачи:** README служит сопроводительной документацией, `/presentation` и `public/arena-presentation.pdf` содержат презентацию, ссылки на прототип и репозиторий размещены в начале файла.

Границы относительно будущего корпоративного продукта: для своей темы используются шаблонные реплики, а не авторский сюжет; кабинет преподавателя хранится локально, результаты переносятся кодом вручную, а учебная эвристика требует проверки тренерами.

## Публичная тестовая версия

Хостинг — GitHub Pages из ветки `gh-pages`. Исходники находятся в `main`; в `gh-pages` попадает только статическая сборка и `.nojekyll`. Для обновления сайта: `npm run deploy` (нужны Git и авторизованный GitHub CLI); чтобы опубликовать в другой подключённый репозиторий, укажите его remote: `DEPLOY_REMOTE=arena npm run deploy`. Скрипт запускает тесты, собирает сайт и публикует артефакты без принудительной перезаписи истории. Публичная версия работает без сервера; локальная нейросеть включается в настройках на устройстве тестировщика. Каждый тестировщик получает собственные настройки и прогресс в своём браузере; общей базы результатов нет.

Для публикации используется `STATIC_EXPORT=true`, а `NEXT_PUBLIC_BASE_PATH` указывает на имя репозитория. Внутренние ссылки используют Next.js Link и учитывают путь репозитория. В обычном локальном запуске эти переменные не нужны.
