## 2. Проблема и решение

Технику переговоров знают многие, а безопасной практики мало. Реальный разговор дорог ценой ошибки. Ролевой тренинг с тренером трудно повторить в удобный момент, лекция не даёт почувствовать последствия решения.

«Арена переговоров» — веб-тренажёр:

- игрок проводит переговоры из шести этапов с собеседником, у которого есть скрытые интересы;
- каждый ход меняет доверие и напряжённость;
- собеседник отвечает на конкретные слова игрока: вопрос, названную цифру или предложение;
- собеседник говорит, чего не хватило в реплике;
- после встречи разбор отделяет итог сделки от оценки навыка;
- повтор честный: собеседник и его скрытые условия остаются теми же.

**Аудитория:**

- начинающие руководители и руководители проектов;
- специалисты по закупкам;
- сотрудники, которые готовятся к карьерному разговору;
- студенты колледжей и корпоративных университетов;
- HR и преподаватели, которым нужен регулярный тренажёр без тренера и серверов.

## 3. Путь пользователя

1. **Легенда и тур.** Короткое знакомство в четыре главы, затем подсветка частей интерфейса: «С чего начать», карта, свой сценарий, прогресс, конструктор, настройки. Тур управляется клавишами ← → Esc и повторяется кнопкой с компасом.
2. **С чего начать.** Три крупные карточки:
   - «Демо: как это работает» — один сыгранный кейс за минуту;
   - «Первая встреча» — базовый уровень с подсказками;
   - кейс заказчика «Алабуга Политех».
3. **Карта и брифинг.** Десять переговоров от городских встреч до совета директоров. Кейсы заказчика — «Завод в ОЭЗ „Алабуга“» и «Алабуга Политех» — открыты сразу. Брифинг показывает цель, BATNA, ZOPA, сложность и тон собеседника.
4. **Шесть этапов диалога:** контакт, интересы, аргументы, варианты, возражения, договорённость. На каждом этапе можно ответить тремя способами:
   - выбрать один из трёх вариантов прямо в ленте;
   - написать свой ответ;
   - сказать его голосом.

   Коуч подсказывает метод, а у края срыва включается таймер.
5. **Разбор.** Состоит из нескольких частей:
   - «Итог»: чем закончилась сделка, на каких условиях, какие интересы раскрыты и какой ценой;
   - «Судьи»: три оценки с цитатой реплики и эффектом хода, подробнее в разделе 4;
   - разбор ход за ходом;
   - Гарвардский метод и матрица компетенций;
   - памятка на следующую встречу.
6. **Повтор и рост:** XP, восемь званий, достижения, «Было ➔ Стало», открытие переговоров следующего масштаба.

## 4. Ключевые механики

- **Доверие** стартует с 50%. Ниже 25% собеседник предупреждает, что готов прервать встречу. Для успеха нужно не меньше 40% доверия.
- **Напряжённость** — отдельная шкала от 5 до 100%.
  - Стартовое значение: 24%, 36% или 48% в зависимости от тона. Продвинутый уровень добавляет 5 пунктов, экспертный — 10.
  - С 45% собеседник говорит осторожнее.
  - С 70% ситуация на грани срыва: слышно тиканье и идёт таймер на ответ.
  - На 100% сделка срывается.
- **Скрытые интересы.** У собеседника их три. Вопрос о приоритетах даёт зацепку, а подхваченная тема раскрывает интерес и повышает доверие.
- **Свободный ответ.** Прозрачная эвристика ищет признаки текущего этапа:
  - вопрос, цифру, обмен уступками, признание позиции;
  - давление, ультиматум, оскорбления.

  Оскорбления ищутся с начала слова, извинение засчитывается только после конфликтного хода. Собеседник отвечает по силе реплики и называет пропущенный элемент.
- **Сложность** меняет порог успеха (52, 65 или 78 из 100) и цену ошибок. На продвинутом уровне штрафы умножаются на 1,15, на экспертном — на 1,3.
- **Итог сделки** (`lib/deal.ts`): статус, условия, раскрытые интересы, цена договорённости.
- **Три судьи** (`lib/judges.ts`): «пошёл бы к нему работать», «отправил бы на переговоры», «доверил бы ресурсы». Каждый вердикт подтверждается эпизодом из диалога: цитатой и эффектом хода.
- **Время ходов.** Каждый выбор хранит отметку времени, разбор показывает, сколько длился ход.

## 5. Локальная нейросеть (On-Device AI)

- **Модель:** Qwen2.5-1.5B-Instruct. Для слабых устройств есть Qwen2.5-0.5B. Модель запускается через [WebLLM](https://github.com/mlc-ai/web-llm) на WebGPU в отдельном Web Worker (`lib/web-llm.worker.ts`), поэтому интерфейс не зависает.
- **Приватность:** текст диалога не покидает устройство. Веса скачиваются с Hugging Face один раз и хранятся в кеше браузера. Серверов, API-ключей и оплаты нет.
- **Роль модели.** Смысл ответа задаёт сценарный движок: реакцию, раскрытие интереса и изменение шкал. Модель пересказывает эту суть живой речью с учётом реплики игрока. Ответ стримится.
- **Защита от ошибок маленькой модели** (`lib/web-llm.ts`). Ответ отклоняется и заменяется сценарным, если модель:
  - теряет смысл ответа (sharesMeaning);
  - повторяет слова игрока (echoesPlayer, повтор из пяти слов подряд);
  - путает роли (swapsRoles);
  - меняет позицию на противоположную (reversesStance).

  Кроме того, удаляются служебные префиксы и ограничивается длина.
- **Второй оценщик.** Модель проверяет реплику по критериям этапа (GAP_CRITERIA). Пропущенный движком элемент засчитывается, только если модель привела цитату из реплики и цитата проходит проверку правдоподобия. Бонус — 2 балла, не больше двух раз за встречу.
- **Надёжность.** Прерывается только идущая генерация: это исправляет ошибку, из-за которой после паузы модель «замолкала». Без WebGPU тренажёр полностью работает на сценарном движке.

## 6. Архитектура

```
Браузер (статический сайт, GitHub Pages)
├── app/page.tsx          — экраны: главная, карта, брифинг, диалог, разбор, прогресс, конструктор, настройки
├── app/presentation      — страница-презентация проекта
├── components/tour.tsx   — пошаговый тур по интерфейсу
├── lib/engine.ts         — сценарии, оценка ходов, доверие, напряжённость, скрытые интересы, исход
├── lib/web-llm.ts        — промпты, проверки ответа модели, оценщик, загрузка модели
├── lib/web-llm.worker.ts — Web Worker для WebLLM
├── lib/deal.ts           — итог сделки
├── lib/judges.ts         — три судьи
├── lib/methods.ts        — методики, Гарвардский метод, компетенции, памятка
├── lib/scenario-library.ts — готовые кейсы (в т.ч. «Алабуга») и JSON-сценарии
├── lib/progression.ts    — звания и карта
├── lib/achievements.ts   — достижения
├── lib/teacher.ts        — локальный кабинет преподавателя, коды отчётов, CSV
├── lib/demo.ts           — демо-маршрут на одну минуту
├── lib/media.ts          — голос (Web Speech) и звук (Web Audio)
└── lib/store.ts          — состояние (Zustand + localStorage)
```

**Стек:**

| Область | Технологии |
|---|---|
| Интерфейс | Next.js 15 (App Router, статический экспорт), React 19, TypeScript |
| Состояние | Zustand persist |
| Анимации и иконки | Framer Motion, Lucide React |
| Нейросеть | @mlc-ai/web-llm |
| Голос и звук | Web Speech API, Web Audio API |

**Данные:**

- Серверной базы нет. localStorage хранит настройки, активную сессию и последние 50 результатов. Очистка данных браузера удаляет прогресс.
- Преподаватель входит по локальному PIN (на устройстве хранится хеш). Ученик передаёт результаты кодом отчёта, группа выгружается в CSV.

**Сайт устанавливается как приложение (PWA).** Интерфейс адаптирован от 320×568 до десктопа, по умолчанию включена тёмная тема, анимации учитывают `prefers-reduced-motion`.

## 7. Конфигурируемость (контур администратора)

Экран «Администратор / Конструктор»:

- сфера, тема, роль, цель, сложность и тон собеседника;
- библиотека из пяти готовых кейсов;
- импорт и экспорт сценариев в JSON.

Настройки влияют на брифинг, порог успеха, стартовую напряжённость и реплики собеседника.

## 8. Запуск и развёртывание

Нужны Node.js 22+ и npm. Проверяемый браузер: Chrome или Chromium; для нейросети нужен WebGPU.

```bash
npm ci
npm run build
npm start
```

Откройте http://localhost:3000. Для разработки есть `npm run dev`.

- Переменные окружения и ключи не нужны.
- Публикация на GitHub Pages: `npm run deploy`. Для другого remote: `DEPLOY_REMOTE=arena npm run deploy`. Скрипт запускает тесты, собирает статический сайт с `basePath` и публикует его в `gh-pages`.

## 9. Тестирование

```bash
npm test          # 93 модульных теста (node:test + tsx)
npm run typecheck # TypeScript без ошибок
npm run build     # production-сборка
```

Тесты покрывают:

- успешные и провальные пути всех сценариев;
- срыв при 100% напряжённости;
- раскрытие интересов и свободные ответы;
- промпты и фильтры нейросети, оценщик с цитатами;
- итог сделки и судей;
- демо-маршрут, достижения и JSON-сценарии.

Сквозной браузерный прогон `docs/browser-smoke.py` (Selenium через chromedriver) проходит победный и проигрышный маршруты, тур и кабинет преподавателя. Он также проверяет адаптивность на размерах 1440×900, 1366×768, 390×844, 375×667 и 320×568.

## 10. Ограничения MVP и развитие

**Ограничения:**

- Нет серверных аккаунтов и синхронизации: результаты группы переносятся кодом отчёта.
- Эвристика оценки учебная, это не валидированный психометрический тест.
- Маленькая модель иногда ошибается, поэтому её ответы проверяются и при сомнении заменяются сценарными.
- Голосовой ввод в Chrome может использовать онлайн-сервис браузера.

**Развитие:**

- библиотека кейсов резидентов ОЭЗ и Алабуга Политеха;
- общая база результатов и отчёты для HR и преподавателя;
- выбор стороны переговоров;
- голосовой ответ собеседника;
- более крупные модели на устройстве.
